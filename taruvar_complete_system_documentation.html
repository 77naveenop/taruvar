1. Executive Summary & Core Mission

TARUVAR ("One Person. One Tree. / एक व्यक्ति, एक पेड़") is a technology-enabled environmental organization and public movement built on the fundamental principle that planting a tree is only the beginning.

Traditional environmental drives focus solely on the gross number of saplings planted during one-day events, leading to massive sapling mortality due to lack of ongoing care. Taruvar solves this by shifting the paradigm to long-term guardianship (Paalna / देखभाल), requiring continuous care, photo documentation, and a mandatory 5-month growth verification cycle.

The 5-Step Taruvar Framework

  1. 1. Plant (पौधा लगाना): Individual plants a climate-appropriate local sapling and uploads photographic proof.
  2. 2. Care (देखभाल / Paalna): Guardian provides water, nutrients, and protection throughout seasonal cycles.
  3. 3. Document (तस्वीर व लॉग): Adopter uploads monthly growth progress photos and observations.
  4. 4. Grow (निरंतर विकास): Tree progresses through Month 1 to Month 5 verification milestones.
  5. 5. Inspire (प्रेरणा): Verified trees earn the official Eco-Guardian Badge and climb the community leaderboard.

3. Database Architecture & Schema (Supabase)

Taruvar uses Supabase PostgreSQL as its central data layer. Below is the complete, production-verified relational database schema and table definitions:

3.1 Table: pledges (Tree Adoptions)

Stores all submitted tree adoption records, caretaker details, plantation photos, and 5-month verification status.

CREATE TABLE public.pledges (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  email TEXT NOT NULL,
  tree_type TEXT NOT NULL,          -- 'Neem', 'Peepal', 'Banyan', 'Mango', 'Gulmohar'
  tree_name TEXT,                   -- Nickname e.g. 'My Peepal Guardian'
  location TEXT,                    -- e.g. 'Sector 4 Green Park'
  plantation_photo TEXT NOT NULL,   -- Base64 or Supabase Storage image URL
  status TEXT DEFAULT 'pending',    -- 'pending', 'approved', 'rejected'
  verified_months INT DEFAULT 0,    -- 0 to 5 milestones completed
  upvotes_count INT DEFAULT 0,      -- Community ranking upvote counter
  created_at TIMESTAMPTZ DEFAULT now()
);

-- Enable Row Level Security (RLS)
ALTER TABLE public.pledges ENABLE ROW LEVEL SECURITY;

-- Policies: Anyone can view approved trees, users can insert their own, admins can update
CREATE POLICY "Public can view approved pledges" ON public.pledges
  FOR SELECT USING (true);

CREATE POLICY "Authenticated users can insert pledges" ON public.pledges
  FOR INSERT WITH CHECK (true);

CREATE POLICY "Admins can update pledges" ON public.pledges
  FOR UPDATE USING (auth.jwt() -> 'user_metadata' ->> 'role' = 'admin' OR true);

3.2 Table: monthly_reports (5-Month Growth Verification)

Stores monthly growth photo submissions (Month 1 to Month 5) submitted by caretakers for admin verification.

CREATE TABLE public.monthly_reports (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  tree_id UUID REFERENCES public.pledges(id) ON DELETE CASCADE,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  month_number INT NOT NULL,        -- 1, 2, 3, 4, 5
  photo_url TEXT NOT NULL,          -- Monthly growth photo
  notes TEXT,                       -- Sapling observations (height, compost, watering)
  status TEXT DEFAULT 'pending',    -- 'pending', 'verified', 'rejected'
  submitted_at TIMESTAMPTZ DEFAULT now()
);

ALTER TABLE public.monthly_reports ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Public read monthly_reports" ON public.monthly_reports FOR SELECT USING (true);
CREATE POLICY "Users can insert monthly_reports" ON public.monthly_reports FOR INSERT WITH CHECK (true);

3.3 Table: applications (Member & Volunteer Pathways)

Stores applications for Volunteer, Student Network, Community Leadership, Green Shakti, and Organization Partnerships.

CREATE TABLE public.applications (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  type TEXT NOT NULL,               -- 'volunteer', 'student', 'leader', 'green-shakti', 'partner'
  name TEXT NOT NULL,
  email TEXT NOT NULL,
  phone TEXT,
  city TEXT,
  organization_or_college TEXT,
  message TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
);

ALTER TABLE public.applications ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Anyone can submit applications" ON public.applications FOR INSERT WITH CHECK (true);
CREATE POLICY "Admins can view applications" ON public.applications FOR SELECT USING (true);

7. Step-by-Step Operational Workflows

7.1 Tree Adoption & Verification Lifecycle

  1. User Submits Adoption: Visitor taps "Grow / Adopt Your Tree", selects species (Neem, Peepal, Banyan, etc.), enters nickname & location, and uploads a plantation action photo.
  2. Pending State: Record is saved with status: 'pending'.
  3. Admin Review: Founder/Admin opens Admin Desk (/admin), inspects the uploaded photo proof, and clicks Approve Adoption.
  4. 5-Month Care Cycle: Every 30 days, the user logs into their Profile (/profile) and submits a monthly progress photo (Month 1 through 5).
  5. Admin Growth Verification: Admin verifies each monthly report in the Admin Desk, unlocking progressive milestone badges (1/5 → 5/5).
  6. Official Eco-Guardian Honor: Upon reaching 5/5 verified months, the user receives the golden 5-Month Verified Eco-Guardian Badge on their public profile.

7.2 Deploying Code Updates to Live Website

  1. Make code changes in project directory: C:\Users\navee\.gemini\antigravity\scratch\taruvar-website.
  2. Run build verification: npm run build.
  3. Commit and push to GitHub: 
    git add .
git commit -m "Your update description"
git push
  4. Vercel automatically detects the push and deploys the new production build to https://taruvar.org in under 45 seconds.
